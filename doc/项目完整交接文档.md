## 4.2 ★ SD 总线三级仲裁（合规核心）

**为什么需要**：板上只有一条 SPI 总线，三个模块都要用。

**仲裁粒度必须是「一个扇区」** —— SD 卡的 CMD17 一旦发出就不能中断。

**优先级**（`sd_bus_arbiter.v`）：
```
wav_urgent  >  txt  >  bmp  >  wav_ok
   ↑            ↑       ↑        ↑
音频告急     字幕扫描  图片    音频补货
(FIFO<128)  (开机一次) (突发)
```

**★ 最容易出错的地方：数据必须"按通道门控"**

```verilog
// data 可以共享（只是个值，没副作用）
assign bmp_sec_read_data = sd_sec_read_data;
// 但 data_valid 和 end 必须门控！
assign bmp_sec_read_data_valid = sd_sec_read_data_valid & (grant_sel == SEL_BMP);
assign bmp_sec_read_end        = sd_sec_read_end        & (grant_sel == SEL_BMP);
```

不加门控的后果：`bmp_read` 内部的字节计数器会把音频扇区的数据也数进去，
计数器多算 512 → 图片数据错位 → **花屏**。

**★ 音频水位门限的坑**（`WAV_MAX_WM`）：
一次授权会灌入一整个扇区 = 128 帧。FIFO 深度 512。
`MAX_WM ≤ 512 - 128 = 384`，代码里取 **320**。
（曾经写成 448 → 水位 448 时授权 → 灌 128 → 576 > 512 → **溢出 → 滋滋噪音**）

**★ 扫描期间不许"告急"**：
```verilog
wire wav_urgent = wav_sec_read & wav_scan_done & (wav_fifo_wrusedw <= WAV_LOW_WM);
//                              ↑ 没有这个门控，扫描会长期霸占总线，把图片装载饿死
```
现象：换图时**黑屏卡好几秒**。

## 4.3 视频流水线对齐铁律

**每插入一个模块，必须用 `video_sync_delay` 把 hs/vs/de 延迟与 RGB 相同的拍数。**

| 模块 | RGB 延迟 | 用的 STAGES |
|---|---|---|
| `image_processor` | 2 拍 | 2 |
| `fade_ctrl` | **2 拍** | 2 |
| `osd_adjust` | 2 拍 | 2 |
| `marquee_osd` | 4 拍（rgb1→rgb2→rgb3→S_rgb_r） | 4 |

> ⚠️ **2026-10-05 修正**：本表原先把 `fade_ctrl` 写成 4 拍，与实际代码不符 ——
> `fade_ctrl.v` 里是 `video_sync_delay #(.STAGES(2))`，即 **2 拍**；
> "rgb1→rgb2→rgb3→S_rgb_r" 那个 4 级寄存器的描述属于 `marquee_osd`。
> 累计延迟：2+2+2+4 = **10 拍**。改流水线前务必以代码为准再数一遍。

**写错的后果**：画面左右偏移、AXIS 的 SOF/EOF 判错 → **撕裂**。

## 4.4 跨时钟域（CDC）做法

**多比特配置**：`common/cfg_cdc.v` 用**翻转握手**（src 域数据稳定后翻转 toggle，dst 域 2FF 同步 + 边沿检测锁存）。

当前用了 5 个实例：
| 实例 | 方向 | 内容 |
|---|---|---|
| `u_cdc_period` | clk → sd_card_clk | 轮播周期 |
| `u_cdc_video` | clk → video_clk | 16bit 配置包（亮度/对比度/模式/调节项/转场/OSD） |
| `u_cdc_period_v` | clk → video_clk | 周期（给 OSD 显示） |
| `u_cdc_auto` | clk → sd_card_clk | 自动轮播开关 |

**视频配置包 `cfg_video[15:0]` 字段分配**：
```
[15:11] 亮度   [10:6] 对比度   [5] 运行/调节模式
[4:3]   调节项 [2]    转场开关 [1] OSD 开关   [0] 预留
```

**单比特信号**：直接 2FF 同步（拨码开关、`load_busy`、按键脉冲）。

**字节/索引流**：**翻转握手**（`txt_read` → `marquee_osd`）：
```
发送方：摆好数据 → 翻转 O_req_tgl → 等 I_ack_tgl 追上 → 再送下一个
接收方：2FF 同步 O_req_tgl → 发现翻转 → 取走数据 → 翻转 O_ack_tgl
```

## 4.5 音频通路（合规关键）

```
wav_read（扫描 RIFF/WAVE → 解析 44 字节头 → 流式输出 PCM）
   ↓ pcm_data = {R[15:0], L[15:0]}
音频异步 FIFO（rfifo_32_32_512，SHOW_AHEAD_EN=1 即 FWFT 语义）
   ↓ 写侧 sd_card_clk 100MHz / 读侧 video_clk 25MHz
audio_player（分数分频累加器产生 48kHz 节拍，underrun 时补静音）
   ↓
hdmi_1_4b_transmitter_core
```

**必须支持的 WAV 格式**（由 `tools/normalize_wav.py` 保证）：
PCM / 48000Hz / 16bit / 立体声 / 标准 44 字节头

**★ `O_audio_valid` 必须无条件保持 48kHz 规律**（underrun 时只把数据置 0），
否则接收端 ACR 失锁 → **爆音**。

## 6.2 Verilog 语法/综合类（★ 高频）

| # | 现象 | 原因 | 修法 |
|---|---|---|---|
| 6 | `Verilog 2000 keyword 'buf' used in incorrect context` | **`buf` 是 Verilog 门级原语保留字**，不能当变量名 | 改名成 `sbuf`。同理不能用 `not/and/or/xor/nand/nor/tran/time/event/wait` 等 |
| 7 | `HDL-8007: keyword 'output' used in incorrect context` | 端口列表里**漏了逗号** | 加逗号（加端口时最容易漏） |
| 8 | `HDL-8007` + 语法错 | `output reg` 的端口用 `assign` 驱动 | 改成 `output wire` |
| 9 | 语法错，指向参数名 | **integer 参数不能做位选**（`PARAM[12:0]`） | 先转成定宽 `localparam` |
| 10 | 移位结果恒为 0 | **Verilog 移位的位宽 = 左操作数位宽**，`6'b100000 << 3` 被截断 | 先补宽再移位：`{3'b000, x[5:0]} << 3` |
| 11 | 编译报"参数不存在" | 改了模块的参数名，顶层例化还在传旧名字 | 两边同步改；或干脆不覆盖用默认值 |
| 12 | `HDL-7225` + 功能异常 | **隐式线网**：信号在声明之前就被使用，被截断成 1 位 | 所有 wire/reg 声明必须放在**第一次使用之前**。★ 真实案例：`bmp_read.v` 的 `bmp_len_cnt`/`pixel_offset`/`width`/`height` 曾声明在 assign 之后（2026-10-05 整理时发现并上移，直接影响缩放正确性） |

| 40 | **上板后图不显示 + 音乐也没有（全黑）** | `bmp_read.v` 的 `O_frame_start` 判断写成 `bmp_len_cnt == pixel_offset`，但像素是 3 字节拼出来的（B→G→R 收满后**下一拍**才把 `bmp_data_wr_en` 拉高），那时字节计数已经走到 `pixel_offset + 3` → **条件永远不成立** → img_scaler 永久卡在 S_IDLE，一个像素都不输出 → 帧缓存写不满 → `load_busy` 一直为 1 → 转场停在黑场（全黑），且图片通道占死 SD 总线 → 音乐被饿死 | 改成 `== pixel_offset + 32'd3`（2026-10-06 修复）。**逐拍仿真验证**：旧判断触发 0 次、新判断触发 1 次（正好是第一个像素输出那拍），像素总数 307200 ✓ |

| 44 | **"下一张"切图错乱**：切到第 4 张后再按，跳回第 1 张（**第 5 张永远显示不出来**）| `sd_card_bmp.v` 里 `next_from_current` 声明成 **2 位**，而 `next_index_limited()` 返回 3 位 → 最高位被截断（索引 4/5/6/7 全变成 0/1/2/3）。**手动切图和自动轮播用的是同一个信号**，所以两条路都错。这是当初"4 张扩到 8 张"时漏改的一处 | 改成 `wire [2:0] next_from_current;`。验证：5 张图时修复前 3→0（第 5 张丢失）、修复后 1→2→3→4→5→1 正常循环 |

**★ 本次同时修掉了 img_scaler 的两个真 bug（仿真已复现 + 已验证修好）**：

1. **输入侧丢像素（致命）**：旧版只在 `S_FILL` 状态里收像素，
   而输出一行的 `S_EMIT` 要 640 拍，期间到达的源像素全丢 ——
   源像素速率约 106 拍/个，也就是**每行丢约 6 个**，480 行累计错位；

   `wp++`（与状态机无关），读侧用"行基址 `rb` + 行内列号 `sx`"取数，
   状态机只等一个 `row_ready`（`occ ≥ I_w`）。**不额外占 BRAM**（仍用原来那块 2048×24）。
2. **`S_DONE → S_WD` 路径**：旧版跳过 `S_HD`、用写死的 480 算宽度，
   导致**第 2 张图起**缩放比例/黑边全错（第 1 张正常，很难查）。
   已改成与 `S_IDLE` 一样先走 `S_HD`。
